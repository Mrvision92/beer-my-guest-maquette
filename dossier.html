Guide de reconstruction dans Wix Harmony

Pour : le développeur qui refait le site de Beer My Guest dans Wix Harmony. Référence visuelle : le prototype (prototype/). C’est une maquette HTML, pas un template importable dans Wix. Le bouton « Notes Wix » (en bas à gauche de chaque page) affiche le modèle de section utilisé pour chaque bloc.

1. Le principe : simple et reproductible

  • Mêmes pages que le site actuel, avec les mêmes textes. Seules les fautes et les majuscules « à l’anglaise » ont été corrigées, et les restes de template supprimés.
  • Une nouveauté : la page « Nos réalisations » remplace « Gallerie/inspiration », avec une page modèle par réalisation.
  • Un seul thème (couleurs + 2 polices + 1 style de bouton) et 7 modèles de section, réutilisés partout. Il suffit de construire chaque modèle une fois, de l’enregistrer, puis de le dupliquer.
  • Aucune fonction avancée : pas de code, pas de filtres, pas d’éléments superposés, pas d’animation complexe.

2. Ce que Harmony permet (état au 1er novembre 2026)

Disponible (documentation officielle Wix) :

  • sections, colonnes, images, textes, boutons ;
  • en-tête figé et menu avec sous-menus ;
  • Wix Gallery avec agrandissement au clic ;
  • popups, animations d’entrée et de survol, Wix Forms ;
  • Wix Stores, Bookings et Blog (déjà installés sur le site) ;
  • version mobile ajustable.

Sources : mobile · thème · menus · galerie · animations · formulaires.

À vérifier dans le compte :

  • le CMS : Wix indique qu’il n’est « pas encore disponible dans tous les comptes » (source). Il ne sert qu’aux réalisations (voir § 6) ;
  • les polices Cormorant Garamond et DM Sans dans la bibliothèque. L’import de polices est impossible (source) ; à défaut, prendre une serif élégante et une sans-serif lisible équivalentes ;
  • le préréglage « grille » de Wix Gallery.

Non disponible :

  • code Velo, CSS personnalisé (source) ;
  • filtres pour le visiteur (source) ;
  • Wix Multilingual : pas de version NL/EN dans Harmony (source) ;
  • passage vers Wix Studio sans reconstruction (source).

6. Nos réalisations

Chaque réalisation contient :

  • une photo de couverture ;
  • un titre ;
  • le type de client, le lieu et l’activité ;
  • un résumé ;
  • le contexte ;
  • le déroulement (3 phrases) ;
  • 4 à 8 photos.

Option A : CMS disponible (recommandée)

  • Collection « Réalisations » avec les champs Titre, Type de client, Lieu, Activité, Résumé (texte), Contexte (texte enrichi), Déroulement (texte enrichi), Image principale (image), Galerie (galerie média), Ordre (nombre).
  • Page liste : un répéteur 2 colonnes connecté à la collection, trié par « Ordre ».
  • Page modèle : une Item page (même mise en page que la fiche du prototype).
  • Pour la cliente : ajouter une réalisation revient à ajouter un élément dans la collection, sans toucher au design.

Option B : sans CMS

  • Une fiche par réalisation : une page modèle, dupliquée pour chaque réalisation, puis textes et photos remplacés.
  • Page liste : des cartes statiques, chacune avec un bouton vers sa page.
  • Pour la cliente : pour ajouter une réalisation, elle duplique une fiche et une carte. C’est simple tant qu’il y a moins d’une douzaine de réalisations.

Les 8 réalisations du prototype sont des exemples fictifs. Ni les textes ni le badge « Exemple » ne sont à reproduire. Il faut les remplacer par les vraies réalisations fournies par la cliente (checklist dans le dossier).

7. Les activités (Wix Stores)

  • Les activités sont déjà des produits Wix Stores. Il suffit d’afficher leur galerie de produits avec le style des cartes (image 4:3 + nom).
  • Masquer le prix à 0 € et la mention « Out of stock » (réglages de la galerie de produits, ou mettre les produits en stock).
  • La page produit native de Wix sert de fiche détaillée. Le texte est déjà rédigé, et le prototype le reprend tel quel dans sa fenêtre « fiche activité ».
  • Supprimer le doublon « Casino de la bière » et les produits et catégories du template (« craft-beers », « beer-glassware »).
